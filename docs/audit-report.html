Bugs & broken edge cases

7 findings
B1High S

Safety gate matches substrings, not words

src/core/nutrition.ts:133

The prediabetes blocklist uses name.includes(b), but its own doc comment promises whole-word matching. Wholesome foods get wrongly rejected by the clinical gate.

What happens
"sugar snap peas"→ contains "sugar"→ 🚫 BLOCKED
"lemon juice"→ contains "juice"→ 🚫 BLOCKED
FIXReuse the word-boundary matchesKey() already written in swaps.ts:50 — that file fixed this exact bug class; the safety gate still has it.
B2High M

One flyer item can satisfy only one ingredient

src/integrations/geminiAnalyzer.ts:305

Assignments are keyed by item in a Map<FlyerItem,string> and the item's price is mutated in place. If the LLM assigns the same item to two ingredients, the second write silently overwrites the first.

What happens
"Onions 2 lb"→ onion ✓ green onion ✓ → last write wins · 1 goes UNMATCHED
FIXKey by the (item, ingredient) pair instead of the item; stop mutating the shared item's rawPrice/size. Live-only & subtle — add a test harness first (T2).
B3Medium S

"Vegan" is treated as "vegetarian"

src/runner.ts:205, 237

A vegan restriction only filters the same 7-item meat list as vegetarian — and that list misses lamb, ham, bacon. Vegans get recipes with dairy & eggs.

What happens
restriction: "vegan"→ 🥚 egg · 🧀 cheese · 🥛 yogurt allowed
FIXSeparate vegan/vegetarian exclusion sets; add dairy, egg, lamb, pork products. A stated hard constraint is being violated.
B4Medium M

Promo text parses as a price

src/core/normalize.ts:84

The bare-number fallback (for legit "1.29 ea") also grabs the first number in marketing copy from live flyers, producing nonsense prices that distort ranking.

What happens
"save $3"→price = $3.00
"3 days only"→price = $3.00
FIXReject promo-shaped strings ("save", "% off", "days") before the fallback. Risky — pin real Backflipp strings in a golden fixture first.
B5Medium S

Installed package's offline mode is broken

src/runner.ts:53 · package.json

The package ships only dist + web, but the default fixture path points at ../test/fixtures/flyers — absent after a global install.

What happens
npm i -g · run offline→ statSync ENOENT 💥
FIXShip fixtures in files, or embed defaults in dist. (Non-issue if repo-checkout is the only intended workflow.)
B6Low S

--radius is unvalidated

src/cli.ts:45

Number(argv[++i]) with no guard. --radius abc → NaN → every store filtered out → a misleading "no nearby stores".

What happens
--radius abc→NaN→ "No nearby stores found"
FIXValidate like --people already does at cli.ts:38.
B7Low S

Gemini recipe output isn't sanitized

src/integrations/geminiRecipe.ts:122

Unlike the URL parser, this path doesn't filter zero/NaN qtyGrams or empty names — NaN line costs could silently skew ranking math.

What happens

FIXApply the same filter the URL parser uses at recipeUrl.ts:379.

Performance

3 findings
P1Medium S

Backflipp fetches terms one-at-a-time

src/integrations/backflipp.ts:131

Sequential HTTP per search term, and it throws on the first failed term. The live week planner sends 40+ terms → 40+ serial round-trips, and one flaky term kills the whole plan.

What happens
term 1→term 2→ … ×40 serial→any 1 fails = total fail
FIXBounded-concurrency fetch; tolerate per-term failures. Directly cuts the "~30s" the UI apologizes for.
P2Medium S

No timeouts on most upstream fetches

backflipp.ts · zippopotam.ts · gemini*.ts

Only the recipe-URL fetcher uses an AbortController. A hung upstream hangs the whole API request indefinitely.

What happens
upstream stalls→request hangs forever ∞
FIXAdd AbortController timeouts mirroring recipeUrl.ts:125.
P3Low S

optimizePlan is O(stores²)

src/core/optimize.ts:201

Enumerates every store pair × ingredients. Fine at flyer scale (~20 merchants) — just don't ever feed it hundreds of stores.

Scaling
20 stores · fine → 500 stores · slow
FIXCap candidate stores before pairing if the source ever grows.
